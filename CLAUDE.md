# Chords App

Приватный сайт для аккордов и текстов песен: общая библиотека песен, личные плейлисты и рекомендации «что спеть». Пользователи — я и друзья, вход по инвайту.

## Стек
- Backend: Java 21, Spring Boot 3, Maven, PostgreSQL, Spring Data JPA, Flyway
- Frontend: React + TypeScript + Vite + Tailwind
- Монорепо: /backend, /frontend. Docker.

## Важное
- Песни хранятся в формате ChordPro, нужно транспонирование
- Mobile-first: песню читают с телефона во время игры (крупный шрифт, тёмная тема по умолчанию)
- Сайт закрытый: без логина ничего не видно, публичного доступа нет

## Фичи (по порядку)
0. Скелет + авторизация
1. Песни: добавление, редактирование, поиск, импорт из формата «аккорды над текстом»
2. Плейлисты и теги
3. Кнопка «сыграл» и рекомендации: давно не играл, по тегу/настроению, случайная песня

## Архитектурные решения

### Песни и ChordPro
- ChordPro парсится, транспонируется и рендерится на фронте библиотекой chordsheetjs. Импорт «аккорды над текстом» → ChordPro тоже через неё.
- Бэкенд хранит исходный ChordPro как TEXT + title, artist, original_key. Бэкенд не парсит ChordPro.
- Источник песен: пользователь вставляет текст вручную. Парсинг внешних сайтов не делаем.
- Массовый парсинг сторонних сайтов не делаем (авторское право, ToS). Песни добавляются вручную, по одной.
- Импорт — ключевой UX шага 1, должен занимать ~1 минуту на песню:
  - одно поле «вставь песню», автоопределение строк с аккордами, title/artist из первых строк, удаление типового мусора;
  - превью рядом с редактором, правка до сохранения;
  - нормализация: H→B, Hm→Bm (русская нотация) при импорте; при показе — настройка нотации;
  - проверка дубликатов по title+artist до сохранения.
- Позже (не сейчас): букмарклет «отправить выделенное в импорт», PWA Share Target для Android.

### Пользователи и доступ
- Spring Security, form login + cookie-сессия (не JWT). CSRF через CookieCsrfTokenRepository (конфигурация для SPA по документации Spring Security 6). Пароли BCrypt.
- Сессии в Postgres (Spring Session JDBC), таймаут 30 дней — чтобы не разлогинивало при деплое.
- Регистрация только по инвайту: invite (code, created_by, used_by, expires_at), одноразовый, срок 7 дней. Открытой регистрации нет.
- Роли USER и ADMIN. ADMIN создаёт инвайты и сбрасывает пароли. Первый ADMIN создаётся при старте из env APP_ADMIN_USERNAME / APP_ADMIN_PASSWORD, если app_user пуста.

### Модель данных
- Общее: song (title, artist, content, original_key, created_by, updated_by, created_at, updated_at). Видят все. Редактирует автор или ADMIN, удаляет только ADMIN. При создании показывать возможные дубликаты (поиск по title + artist).
- Личное (user_id, всегда фильтр по текущему пользователю, чужой ресурс → 404):
  - playlist + playlist_song (position)
  - tag + song_tag (теги личные: настроение, «у костра» и т.п.)
  - play_event (song_id, played_at)
- Рекомендации считаются из play_event текущего пользователя.

### UI
- Цвета, шрифты, радиусы — только через токены темы (Tailwind 4 `@theme`). Никаких hex-цветов и font-family прямо в компонентах.
- Позже: ретро-тема по макетам https://claude.ai/artifact/TLwcCTxWNzSqCzxNBmMF1d (тёмно-коричневый фон, кремовый текст, горчичный/оранжевый/бирюзовый акценты; Unbounded, Rubik, Lobster). Пока не внедряем.

### Backend-конвенции
- REST JSON под /api. DTO — Java records, entity наружу не отдаём.
- Схема БД меняется только миграциями Flyway, ddl-auto=validate.
- Поиск: ILIKE по title/artist (позже можно pg_trgm).
- Интеграционные тесты на Testcontainers (Postgres).

### Деплой
- Multi-stage Dockerfile: сборка фронта → static Spring Boot → jar. Один контейнер app + postgres в docker-compose.
- В деве: Vite dev server с proxy /api → localhost:8080.
- Секреты только через env, .env не коммитим, есть .env.example.

## Не делаем пока
